# wagate — свой шлюз WhatsApp (как Green-API)

Шлюз подключается к WhatsApp как ещё одно «связанное устройство» телефона, так же, как WhatsApp Web. Работает по протоколу WhatsApp Web через библиотеку [Baileys](https://github.com/WhiskeySockets/Baileys), браузер не нужен. API совпадает с Green-API, поэтому наши скрипты (`camirix/wa_inbox.py`, `camirix/wa_send.py`) работают с ним без изменений: достаточно поменять адрес в `GREEN_API_URL`.

**Отличия от Green-API**
- Не нужна подписка.
- Переписка хранится у нас.
- Правила отправки встроены в сам шлюз: лимиты, рабочие часы адресата, стоп-лист.

## ⚠️ Риск, о котором нужно знать
Официально WhatsApp разрешает подключаться только своими приложениями и Business API. Сторонние клиенты вроде Baileys, Green-API, Wappi нарушают условия использования. **WhatsApp может заблокировать номер**, особенно за жалобы на холодные сообщения.

**Что снижает риск**
- **Отдельный рабочий номер.** Не личный. Номеру желательно хотя бы 1–2 недели обычной жизни, прежде чем писать с него холодные сообщения.
- **Встроенные лимиты:** до 15 новых чатов в день, пауза 2 минуты между ними, только рабочие часы и будни адресата.
- **Одно повторное касание.** После просьбы «не пишите» номер уходит в стоп-лист навсегда.
- **Второй номер про запас.** Если шлюз видит блокировку, `getStateInstance` отдаёт `blocked`, и отправка останавливается.

## Личные переписки не читаются

Шлюз видит только чаты с лидами. Лид — это номер, которому писал сам шлюз, или номер, который агент зарегистрировал через `wagateAllow`: `wa_inbox.py` передаёт туда только те номера со страницы, куда сообщение уже ушло.

Со всеми остальными сообщениями шлюз обращается так:
- **Не пишет никуда:** ни в базу, ни в файлы, ни в лог.
- **Не отдаёт** через API и вебхук, в том числе агенту.
- **Держит только в оперативной памяти до 48 часов.** Это нужно на случай, если ты отправил лиду сообщение вручную и он ответил раньше, чем агент зарегистрировал номер. Если номер не стал лидом, сообщение исчезает.
- **Историю переписки с телефона не загружает.** Группы, статусы и каналы не обрабатывает. В логах нет номеров из личных чатов.

Техническая оговорка: по протоколу WhatsApp каждое связанное устройство получает все сообщения в зашифрованном виде и расшифровывает их, так же как WhatsApp Web на компьютере. Шлюз отбрасывает чужие сообщения сразу после расшифровки. Полностью исключить их получение может только отдельный рабочий номер, на который личные переписки не приходят. Это лучший вариант.

## Запуск

### Бесплатно, без сервера и карты: Render + Neon
Нужен только браузер, всё можно сделать с телефона.

1. **База (Neon).** Зарегистрируйтесь на neon.tech → Create project. На главной проекта скопируйте **Connection string** (`postgresql://…?sslmode=require`).
2. **Шлюз (Render).** Зарегистрируйтесь на render.com → New → **Web Service** → **Public Git Repository**. Укажите:
   - адрес репозитория `https://github.com/velorievvork-pixel/SaaS`;
   - Branch `claude/sdr-service-automation-opruv0`;
   - Root Directory `wagate`;
   - Runtime **Node**;
   - Build `npm ci --omit=dev`;
   - Start `node src/index.js`;
   - Instance type **Free**.
3. **Environment variables** (там же):
   - `WAGATE_TOKEN` — кнопка **Generate**;
   - `DATABASE_URL` — строка из Neon;
   - `PAIR_PHONE` — рабочий номер цифрами, например `77011234567`.
4. **Create Web Service.** Через 2–3 минуты откройте вкладку **Logs**. Там будет строка `КОД ПРИВЯЗКИ для +7…: ABCD-1234`. На телефоне: WhatsApp → Связанные устройства → Привязка устройства → «Связать по номеру телефона» → введите код. Новый код появляется каждые 3 минуты, пока номер не привязан.
5. Адрес шлюза вида `https://<имя>.onrender.com` виден вверху страницы сервиса.

**Как это держится бесплатно**
- **Сон.** Бесплатный Render усыпляет сервис через 15 минут без запросов. Шлюз сам обращается к своему адресу каждые 10 минут (`RENDER_EXTERNAL_URL` Render задаёт сам) и поэтому не засыпает. 750 бесплатных часов в месяц хватает на одну службу круглосуточно.
- **Перезапуски.** Диск у бесплатного Render стирается при каждом перезапуске. Поэтому сессия WhatsApp, сообщения и стоп-лист лежат в Neon, и повторная привязка после перезапуска не нужна.
- **Ограничения.** Neon бесплатно даёт 0,5 ГБ, этого хватает на годы переписки. Журнал старше 30 дней удаляется.

### На своём сервере (VPS)

**Проще всего (без SSH-настройки руками):** при создании сервера вставить `setup/cloud-init.sh` в поле «Cloud-init script» / «User data». Скрипт всё установит, сгенерирует токен, запустит шлюз и HTTPS на бесплатном адресе `<ip>.sslip.io`. Потом один раз на сервере: `sudo /opt/wagate/setup/pair.sh <рабочий номер>` — покажет код привязки и настройки для агента. Нужна Ubuntu 24.04 (в 22.04 нет пакета caddy). Бесплатно — Oracle Cloud Always Free.

Вручную:

Нужен сервер, который работает постоянно: VPS за 300–1000 ₽ в месяц, 1 ГБ памяти достаточно. Контейнер Claude Code для этого не подходит: он временный.

```bash
# на сервере (Ubuntu), Node.js 20+
git clone https://github.com/velorievvork-pixel/saas && cd saas/wagate
npm ci --omit=dev
cp .env.example .env    # впишите WAGATE_TOKEN
node src/index.js
```

Или в Docker:
```bash
docker build -t wagate . && docker run -d --restart=always --env-file .env -v wagate-data:/data -p 127.0.0.1:3000:3000 wagate
```

Для автозапуска без Docker есть `wagate.service` (systemd).

### Привязка телефона (один раз)

**QR-код**
1. Откройте `GET /waInstance{ID}/qr/{TOKEN}` и получите `{"type":"qrCode","message":"<base64 PNG>"}`.
2. Покажите картинку: например, вставьте `data:image/png;base64,<message>` в адресную строку браузера.
3. На телефоне: WhatsApp → Настройки → Связанные устройства → Привязать устройство.

**Код по номеру** (удобнее, если сервер без экрана)
1. Отправьте `POST /waInstance{ID}/getAuthorizationCode/{TOKEN}` с телом `{"phoneNumber": 77011234567}`.
2. В ответ придёт код, например `ABCD-1234`.
3. На телефоне: Связанные устройства → Привязать по номеру телефона → введите код.

Сессия сохраняется в `data/auth`, после перезапуска привязка не нужна. Если отвязать устройство с телефона, удалите `data/auth` и привяжите заново.

### Доступ снаружи
По умолчанию шлюз слушает только `127.0.0.1`. Если скрипты работают на другой машине, поставьте перед шлюзом Caddy с HTTPS:
```
wa.example.com {
  reverse_proxy 127.0.0.1:3000
}
```
Токен передаётся в адресе запроса, как у Green-API, поэтому без HTTPS шлюз наружу не открывать.

## API

Все запросы имеют вид `/waInstance{WAGATE_ID}/{метод}/{WAGATE_TOKEN}`.

| Метод | Запрос | Ответ |
|---|---|---|
| `getStateInstance` | GET | `{"stateInstance": "authorized" \| "notAuthorized" \| "starting" \| "blocked"}` |
| `qr` | GET | `{"type":"qrCode","message":"<base64 png>"}` или `{"type":"alreadyLogged"}` |
| `getAuthorizationCode` | POST `{"phoneNumber": 7701…}` | `{"status":true,"code":"ABCD-1234"}` |
| `sendMessage` | POST `{"chatId":"77011234567@c.us","message":"…"}` | `{"idMessage":"…"}` |
| `checkWhatsapp` | POST `{"phoneNumber": 7701…}` | `{"existsWhatsapp": true}` |
| `lastIncomingMessages` | GET `?minutes=1440` | Массив сообщений в формате Green-API |
| `lastOutgoingMessages` | GET `?minutes=1440` | То же для отправленных |
| `receiveNotification` | GET | `{"receiptId":1,"body":{"typeWebhook":"incomingMessageReceived",…}}` или `null` |
| `deleteNotification/{receiptId}` | DELETE | `{"result": true}` |
| `wagateLimits` | GET | Наш метод: новые чаты за сегодня, лимиты, размер стоп-листа |
| `/health` | GET, без токена | `{"ok":true,"state":"authorized"}` |

Если задан `WEBHOOK_URL`, каждое входящее сообщение сразу отправляется туда POST-запросом. Шлюз делает 3 попытки. Если все не удались, сообщение всё равно доступно через `lastIncomingMessages`.

### Когда шлюз не отправляет

| Код | `error` | Что значит |
|---|---|---|
| 400 | `bad_phone`, `empty_text`, `too_long` | Ошибка в запросе |
| 403 | `stop_list` | Человек просил не писать («не пишите», «стоп», «удалите номер»…). На «не интересует» это не срабатывает: одно вежливое закрывающее сообщение допустимо. |
| 404 | `no_whatsapp` | На номере нет WhatsApp |
| 409 | `duplicate_24h` | Этот текст уже уходил на этот номер за сутки |
| 425 | `off_hours`, `weekend`, `unknown_country` | У адресата нерабочее время. Часовой пояс определяется по коду страны: KZ +5, RU +3, KG +6, UZ +5 и т.д. |
| 429 | `daily_new_chat_limit`, `too_soon` | Исчерпан лимит новых чатов на день или не выдержана пауза между ними |
| 503 | `whatsapp not authorized` | Телефон не привязан или номер заблокирован |

Лимит новых чатов считает только тех, с кем переписки ещё не было. Ответы в живом диалоге под лимит не попадают, но рабочие часы адресата действуют и для них.

## Как этим пользуются наши скрипты
```bash
export GREEN_API_URL=https://wa.example.com GREEN_API_ID=1101000001 GREEN_API_TOKEN=…

# ответы лидов и автоматическая пометка «Молчат»
python3 camirix/wa_inbox.py --outbox <выгрузка страницы> --json

# отправка с проверкой текста (суммы, выдумки, стиль) и правилами шлюза
python3 camirix/wa_send.py --phone "+7 701 123 45 67" --file msg.txt --kind first
```

## Тесты
```bash
npm test
```
Тесты проходят без WhatsApp, вместо Baileys подставлена заглушка. Они проверяют:
- номера и часовые пояса;
- стоп-слова;
- разбор сообщений, в том числе новые адреса LID;
- все правила отправки;
- что два одновременных запроса не обходят дневной лимит;
- API в формате Green-API: токен, QR, код привязки, очередь уведомлений, размер запроса.

Совместимость с `wa_inbox.py` проверена запуском этого скрипта против шлюза.
